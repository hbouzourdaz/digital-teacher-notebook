# دفتر الأستاذ الرقمي — Digital Teacher Notebook

تطبيق سطح مكتب شخصي للأستاذ في التعليم المتوسط، يحوّل **الدفتر اليومي** و**دفتر التنقيط** الورقيين إلى نظام رقمي
سريع ومترابط، ويعمل **بالكامل دون إنترنت**.

> المبدأ الأساسي: **أدخل المعلومة مرة واحدة واستعملها في كل مكان.**
> تُدخل الجدول الأسبوعي مرة واحدة، فيعرف التطبيق القسم والمادة واليوم والساعة والحصة، ثم يستعملها في الدفتر اليومي
> والحضور والتنقيط والتقييم والتقارير والطباعة.

## المزايا

| الوحدة | ما تفعله |
| --- | --- |
| لوحة التحكم | تاريخ اليوم، السنة الدراسية، بطاقات إحصائية، حصص اليوم، الحصة الآنية والقادمة |
| يومي | خط زمني لحصص اليوم مع أزرار: تسجيل الحصة، الحضور، التنقيط، فتح القسم |
| الجدول الأسبوعي | شبكة حقيقية (الأحد → الخميس × 8 خانات زمنية) مع سحب وإفلات، نسخ/لصق، تكرار، وحذف |
| الدفتر اليومي | الأقسام المسندة + التوزيع الأسبوعي + سجلات الدروس (التاريخ، التوقيت، القسم، العنوان والمراحل، ملاحظات) |
| الأقسام | إدارة الأقسام، الاستنساخ، الإحصاءات، تقرير القسم |
| التلاميذ | إضافة/تعديل/حذف/أرشفة، بحث، ترتيب يدوي، نقل بين الأقسام مع سجل، استيراد CSV/XLSX، تصدير CSV |
| الحضور | إدخال سريع («الجميع حاضر» ثم تعديل الغائبين)، ملخّص لكل تلميذ، سجل تفصيلي |
| دفتر التنقيط | كل الأعمدة قابلة للإدخال (فرض/اختبار/تقويم مستمر)، أعمدة ثابتة، تنقّل بالكيبورد، حفظ تلقائي، تلوين المعدلات حسب العتبة |
| التقييمات | فروض واختبارات وأنشطة، إدخال العلامات، نسخ تقييم سابق، ظهور تلقائي في التنقيط |
| التوزيع السنوي | الدروس لكل مستوى وفصل مع الحالة والتواريخ ونسبة الإنجاز، وتحديث تلقائي عند تسجيل الحصة |
| بنك الدروس | عناوين ومراحل سير الحصص والأهداف، تُدرج في أي حصة بضغطة |
| الفروض والاختبارات ومجالس الأقسام | أحداث السنة + تقويم شهري موحّد (حصص وتقييمات وأحداث) |
| التقارير | تقرير القسم، الطالب، الغياب، التقييمات، التقدّم، السنة |
| الطباعة | 11 وثيقة A4 بالعربية (RTL) مع غلاف لكل وثيقة، ترقيم أوراق، وطبع صفحة أو مدى، ومعاينة وطباعة وحفظ PDF |
| الأرشيف | فتح السنوات السابقة للبحث والطباعة مع منع التعديل بالخطأ |
| النسخ الاحتياطي | يدوي وتلقائي (يومي/أسبوعي) مع فحص سلامة واستعادة آمنة |
| الإعدادات | الأستاذ، المؤسسة، المواد، المستويات، السنوات الدراسية، صيغة النقاط، الطباعة، قفل PIN |

### صيغة حساب المعدل

التطبيق **لا يفترض صيغة رسمية**. أعمدة دفتر التنقيط المرجعي محفوظة كما هي
(الكراس، المشاركة، السلوك، الوظائف ← التقويم المستمر، ثم الفرض، معدل النشاطات، الاختبار، المعدل)، والأوزان
يحدّدها الأستاذ من: **الإعدادات → صيغة النقاط**، ويظهر له دائماً «صيغة الحساب الحالية» كنص مقروء.

## التشغيل في وضع التطوير

```bash
npm install
npm run dev
```

### عن `better-sqlite3` (مهم)

`better-sqlite3` حزمة أصلية (native) تُبنى لكل واجهة ABI مختلفة: نسخة لواجهة **Node** (للتشغيل والاختبارات)
ونسخة لواجهة **Electron** (للتطبيق والمثبّت)، ولا تصلح الواحدة مكان الأخرى.

لذلك يعتني المشروع بالأمر تلقائياً عبر `scripts/sqlite-runtime.mjs`:

| الأمر | النسخة المستعملة |
| --- | --- |
| `npm run dev` / `npm start` | Electron — في `node_modules/better-sqlite3` |
| `npm run dist` / `npm run dist:dir` | Electron — نفس المجلد |
| `npm test` | Node — في `node_modules/.node-abi/better-sqlite3` |
| `npm run rebuild` | Electron فقط |

النسختان في **مجلدين منفصلين**، فيمكن تشغيل التطبيق (`npm run dev`) وتشغيل الاختبارات في الوقت نفسه دون
أي خطأ «resource busy or locked». يمكن تجهيزهما يدوياً عند الحاجة:

```bash
npm run sqlite:electron
npm run sqlite:node
```

التجهيز يعتمد على النسخ الجاهزة (prebuild) وتُخزَّن مؤقتاً على الجهاز، فلا يحتاج البرنامج نفسه إلى إنترنت أبداً.

بيانات التطوير تُخزَّن في مجلد `userData` الخاص بإلكترون، ولا تلمس ملفات المشروع.

### أيقونة البرنامج

الأيقونة مُضمّنة في `build/icon.ico`، ويمكن إعادة توليدها (بدون أي مكتبة خارجية):

```bash
npm run icon
```

## البناء وإنشاء مثبّت Windows

```bash
npm run build      # فحص الأنواع + بناء main/preload/renderer
npm run dist       # إنشاء مثبّت NSIS  →  release/
npm run dist:dir   # نسخة غير مضغوطة (مجلد) للفحص السريع
```

الناتج: `release/دفتر الأستاذ الرقمي-1.0.0-setup.exe` (اسم الملف من `electron-builder.yml`).

- المثبّت يحتوي **البرنامج فقط**، ولا يحتوي أي قاعدة بيانات.
- التحديث أو إلغاء التثبيت **لا يحذف** قاعدة البيانات ولا النسخ الاحتياطية ولا المرفقات (كلها في `userData`).
- أغلق التطبيق قبل إعادة البناء إذا كان مفتوحاً من `release/win-unpacked`.

### إذا فشل `npm run dist` بخطأ «Cannot create symbolic link»

يحدث هذا على Windows عندما لا تُنشئ أداة فكّ الضغط روابط رمزية من أدوات التوقيع (winCodeSign) بسبب الصلاحيات.
الحل الأبسط:

```bat
scripts\build-installer.cmd
```

شغّله بالنقر بزر الفأرة الأيمن ثم **تشغيل كمسؤول** (Run as administrator). بديل آخر: تمكين
**وضع المطوّر** (Developer Mode) في إعدادات Windows.

## الاختبارات

```bash
npm test           # تشغيل مرة واحدة
npm run test:watch # مراقبة
```

تغطي الاختبارات: حساب المعدل والصيغ، معالجة التواريخ المحلية، كشف تعارض الجدول، اختيار الحصة الحالية/القادمة،
أدوات CSV والنص العربي، عقد قنوات IPC، وتعريف المخطط (وتنفيذ المخطط على SQLite في الذاكرة عند توفر المحرّك).

> ملاحظة: `npm test` يستعمل نسخة `better-sqlite3` الخاصة بـ Node من `node_modules/.node-abi/`، فتعمل اختبارات
> قاعدة البيانات كاملة حتى لو كان التطبيق مفتوحاً في نفس الوقت.

## بنية المشروع

```
src/
  main/                    # العملية الرئيسية (Node + SQLite)
    database/              # الاتصال، نظام الترقيات، ملفات .sql
    repositories/          # طبقة الوصول للبيانات (Prepared Statements فقط)
    services/              # منطق العمل: التنقيط، لوحة التحكم، البحث، التصدير، البيانات التجريبية
    ipc/                   # تسجيل كل قنوات IPC مع تحقق Zod
    backup/                # النسخ الاحتياطي والاستعادة وفحص السلامة
    printing/              # بناء وثائق A4 + توليد PDF
    filesystem/            # المسارات، قراءة ملفات CSV/XLSX
  preload/                 # جسر contextBridge (واجهة بيضاء قائمة)
  renderer/src/            # واجهة React (RTL)
    components/            # مكوّنات الواجهة + شاشات مشتركة (تسجيل حصة، الحضور)
    pages/                 # شاشات التطبيق
    store/                 # حالة التطبيق (Zustand) — ليست مصدر الحقيقة
    hooks/                 # جلب بيانات من IPC
    styles/                # Tailwind + الخطوط المحلية
  shared/                  # مشترك: أنواع، ثوابت، مخططات Zod، دوال خالصة، عقد IPC
resources/fonts/           # الخطوط المحلية (Amiri / Tajawal)
build/                     # موارد البناء (icon.ico / icon.png)
scripts/                   # أدوات التطوير: تجهيز SQLite، توليد الأيقونة، بناء المثبّت
tests/                     # اختبارات الوحدة (Vitest)
docs/                      # الوثائق التفصيلية
```

التفصيل في [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## قاعدة البيانات والنسخ الاحتياطي

- المحرّك: **SQLite** عبر `better-sqlite3`، مع Prepared Statements فقط ولا SQL خام من الواجهة.
- الموقع: `app.getPath('userData')/notebook.db` — خارج مجلد التثبيت.
- الترقيات: `src/main/database/migrations/00X_*.sql` مع `user_version`، ونسخة احتياطية تلقائية قبل كل ترقية.
- النسخ الاحتياطي: `userData/backups/YYYY-MM-DD_HH-mm-ss.db`، مع سجل في قاعدة البيانات وفحص سلامة `integrity_check`.
- الاستعادة: نسخة أمان من الوضع الحالي → استبدال الملف → إعادة تحميل الواجهة. لا تُحذف أي نسخة.

التفصيل في [DATABASE.md](docs/DATABASE.md).

## الطباعة

11 وثيقة مدعومة: الجدول الأسبوعي، الدفتر اليومي، قائمة القسم، سجل الغياب، دفتر التنقيط، نتائج الفصل،
الفروض والاختبارات ومجالس الأقسام، تقرير القسم، تقرير التلميذ، التوزيع السنوي، تقرير الأستاذ.

- معاينة داخل التطبيق (iframe معزول) → طباعة النظام عبر نافذة أصلية مركّزة بمقاس A4 والاتجاه الصحيح، أو «حفظ PDF» عبر `webContents.printToPDF`.
- زر «طباعة» في كل شاشة يفتح مركز الطباعة على الوثيقة الصحيحة بسياقها (القسم، الفصل، المدى، التلميذ).
- **غلاف لكل وثيقة**: ورقة أولى بهوية المؤسسة والأستاذ والفترة ومؤشرات الوثيقة ومحتواها وسطرَي إمضاء.
- **ترقيم أوراق حقيقي «صفحة X من Y»** يُبنى بعد قياس ارتفاع كل وحدة في نافذة إلكترون مخفية، ومعاينة مطابقة تماماً لما يُطبع.
- **طبع ورقة أو مدى**: «كل الأوراق / الغلاف فقط / من صفحة إلى صفحة»، وقائمة أوراق مسمّاة لطبع يوم أو قسم بضغطة مع بقاء ترتيب الترقيم.
- **معاينة تُصغَّر لتناسب اللوحة تلقائياً** بلا شريط تمرير أفقي، وكل الشاشات بشريط تمرير واحد رقيق (الصفحة) وجداول تُمرَّر أفقياً داخل بطاقتها فقط.
- رأس الوثيقة: المؤسسة، الأستاذ، المادة، السنة الدراسية، تاريخ الطبع، والشعار إن وُجد — ويمكن إخفاؤه خانةً.
- كل الوثائق تقرير داخلي للعمل الشخصي ولا تدّعي أي صفة رسمية.

التفصيل في [PRINTING.md](docs/PRINTING.md).

## الخطوط

ضع ملفات الخطوط في `resources/fonts/`:

```
Amiri-Regular.ttf / Amiri-Bold.ttf                          → الوثائق والطباعة
Tajawal-Regular/Medium/Bold/ExtraBold.ttf                   → واجهة التطبيق
OFL-Amiri.txt / OFL-Tajawal.txt                             → رخصة SIL OFL 1.1
```

- خط الوثائق والطباعة: **Amiri** (مضمّن في CSS بـ `@font-face` بمسار محلي `file://`).
- خط الواجهة: **Tajawal** بكل أوزانه (400/500/700/800) مع بدائل نظامية.
- الخطّان **مرفقان داخل الحزمة** برخصة SIL OFL 1.1 (المصدر: Google Fonts) — لا تُنزَّل وقت التشغيل.
- عند غياب الملفات يستعمل التطبيق خطوط النظام العربية البديلة ويبقى صالحاً للعمل والطباعة.
- `npm run fonts:sync` ينسخ الخطوط إلى `src/renderer/public/resources/fonts` لتعمل في وضع التطوير أيضاً
  (يعمل تلقائياً قبل `dev` و`build`).

لا يوجد أي استدعاء لـ Google Fonts أو أي CDN — لا في الواجهة ولا في الوثائق.

## ضمانات الخصوصية والعمل دون إنترنت

- لا استدعاءات شبكية للوظائف الأساسية (`connect-src 'self'` في CSP، ولا `fetch` في المنطق الأساسي).
- لا Firebase / Supabase / MongoDB Atlas / REST API / Cloud API.
- لا Analytics ولا Telemetry ولا تتبّع.
- المرفقات محلية فقط ولا تُرفع إلى أي مكان.
- قفل PIN يمنع الوصول عبر التطبيق، لكن تنبيه صريح: **ملف SQLite غير مشفّر** على القرص.
